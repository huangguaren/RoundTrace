## 1. 产品目标与验收闸门

RoundTrace 是阿瓦隆线下对局的离线记录和复盘工具。当前优先保障：历史记录不会被无意删除；复盘输入一致；错误后可恢复；推论不会因畸形数据生成错误的确定结论。保留 Android Kotlin + Compose + Room 架构、无须后端或云端账号。

## 2. P0：历史安全编辑（RT-NX06-SAFE）

### 2.1 用户故事

- **US-01 只看历史**：在任务进度条点第 N 任务，立即展示该任务历史记录和可编辑条目；不触发回滚或新增事件。点击“完成”返回最新任务，不改变历史数据。
- **US-02 预览影响**：点击历史条目，编辑提案/投票/任务结果，点击保存时先看到修改内容及实际受影响事件列表（任务、提案、类型、原因、操作）。此时尚未修改历史。
- **US-03 取消**：在确认框点击“取消”，历史事件不发生任何写入或撤销；本次输入留在编辑草稿，允许继续修改。
- **US-04 确认**：点击“确认修改并重置受影响记录”，在同一个事务里核实快照没有过期、修订目标事件，并仅撤销被确认的、确实依赖本次变更的事件。
- **US-05 版本冲突**：等待确认期间历史被另一动作修改，禁止使用旧预览；显示“记录已变化，请重新确认”，保留输入并刷新影响清单。
- **US-06 风险不明**：影响范围无法准确计算时只显示冲突/需要人工处理，不进行宽泛的批量删除。

### 2.2 历史依赖规则（先固定安全边界）

| 修改对象 | 可能依赖对象 | 需求行为 |
|---|---|---|
| `TeamProposed` 的队长或成员 | **同一任务、同一提案**的投票/决议，以及依赖该提案的任务牌 | 按提案号和通过关系计算，明确列出；不得直接删除整个后续任务 |
| `TeamVoteRecorded` | 既有 `TeamProposalResolved`（可能矛盾） | B35：决议是不可编辑的现场事实；仅修订投票，若与决议矛盾，必须标记冲突并要求明确修复路径；不得静默改决议 |
| `MissionResolved` | 后续任务的有效性、终局状态等 | 比较修改前/后的规则重放；仅当具体后续事件确实失去有效前提时进入撤销清单；任务胜负投影自动重算不等于撤销后续数据 |
| 仅修改显示名、头像、笔记 | 通常不影响规则事件 | 不得因这类非规则数据变更删除任务或投票 |

**决定性约束**：事件类型间可能含多重依赖，不允许仅凭 `logicalPosition > cutoff` 推定全部受影响；`retractAfterOrder()` 不得用于安全编辑的依赖撤销。删除在实现中指 **事件标记 `retracted=1`，保留审计链**，不是 SQL `DELETE`。

### 2.3 前置确认与原子性

- 确认框必须包含目标修改差异、受影响事件的稳定 ID/可读摘要、预计被重置的数量及理由；无影响也显示明确的“无需重置其他记录”。
- 确认前不得调用历史 `reviseEvent` / `retractEvent` / `retractAfterOrder`。原始草稿自动保存可保留，但不得混淆为历史事件修改；用户取消的零写入断言针对历史事件及派生状态。
- 确认时在 **一个 Room 事务** 内校验目标事件仍有效、对局归属、所依据的事件版本/相关依赖集合未变化、用户确认的集合仍与规则判定吻合；校验失败必须整体回滚。
- 单击、重复点击、协程取消、数据库写入失败都必须有明确信息，不得显示假成功；失败时旧事件仍有效且保留用户草稿。
- 仅 `TEAM_PROPOSED`、`TEAM_VOTE_RECORDED`、`MISSION_RESOLVED` 可编辑（B35/B37）。

### 2.4 验收标准（必须具备自动化证据）

A01 浏览历史零写库；A02 退出恢复最新位置；A03 提案预览列出同提案依赖；A04 投票修改不静默变更决议；A05 任务结果变更仅影响真实依赖；A06 无影响显示 0 条；A07 取消零历史写入；A08 取消保留草稿；A09 确认一个事务写完；A10 注入失败整体回滚；A11 并发修改触发重新预览；A12 重复确认只执行一次；A13 跨对局 ID 无法操作；A14 非白名单不可编辑；A15 无关后续笔记/声称仍有效；A16 修订保持 `logicalPosition` 和 `revisionSeq` 语义；A17 B34 胜负计数按明确结果重算；A18 视角与导出结果不泄漏/不复活旧版本。

## 3. P1：响应式一致性（RT-NX02-SNAP）

当前 `getBundle()` 已用 `withTransaction`，`observeBundle()` 仍四路 `combine()`。要求一次发射由同一个事务内的完整读取结果构成；订阅跨 `matches`、`participants`、`role_assignments`、`match_events` 的失效；首发、删除、修订、揭晓、角色更新、成员更新可自动刷新。

验收：模拟写入时 `matches.status`、角色揭晓、有效事件同步更新；每次发射必须满足跨表一致性不变量；无中间态混合；对局删除发射 `null`；无无界全量缓存、重复无意义重放；并发首次提案不生成两个 `QuestStarted`。

## 4. P1：首页错误恢复与复盘效率（RT-NX03-RETRY/PERF）

首页的 Loading / Data / Error 必须在每次筛选或重试中独立表达。首次失败后重试能够创建新的查询订阅并恢复结果；快速切换筛选不会回退到过期列表；搜索/筛选状态和错误消息一致。已有复盘快照复用应保留；视角、逻辑位置、撤销/修订变化都重算本次内容，不做 B29 禁止的全局分析缓存。

验收：查询首次失败、第二次成功；连续两次失败再成功；筛选切换；多收集者不会导致不合理双订阅；测量同等负载下底层订阅数、知识快照调用数及运行时间（记录环境、样本数量、重复次数和统计量）。禁止捏造百分比。

## 5. P1：推论数据有效性（RT-NX01-EDGE）

对玩家数不在 5–10、任务号不在 1–5、负数/越界失败牌、队伍少人/多人、重复/越界座位、失败牌与任务观察结果冲突等，必须按字段依赖选择抑制确定性推论或输出 `UNKNOWN` 警告。不能把不可能的坏人数量作为 `RULE_CERTAIN`。遵守 B34 的已知任务结果计数规则与个人/公开/上帝视角隐私隔离。正常场景保持原有推论规则。

## 6. 明确排除

- NX-05 独立设备验收：**CANCELLED**；现存 JVM / Robolectric / AndroidTest 代码不得删除。
- 不在本轮新增云同步、账号、AI 自动判角色、狼人杀规则引擎、大型 UI 改版或数据库 Schema 迁移。
- 不为了凑绿色而删除失败测试、不通过 `catch(Exception){}` 隐藏错误、不通过全量清空修复历史。

## 7. 核心需求通过后：v0.5.0 产品增强候选（下一个真正功能版本）

> 仅做需求储备，不包含在本次 P0/P1 整改交付内。

**F05-01 玩家行为时间线（优先）**：按座位聚合该玩家担任队长、参加任务、投票、声称、被提及证据等事件；可按任务与事件类型筛选、点击跳转至对应复盘位置。按视角过滤私人信息，不做无法证实的个人出牌归因。

**F05-02 “当时判断 vs 最终真相”**：在合法终局与揭晓条件满足后，显示历史时刻可知信息与揭晓后的真实身份对照；明确标注“当时不知道”，永不把终局身份回灌到历史视角。普通未揭晓对局不得显示真实角色。

**F05-03 快速记录模式**：现场一键切换队长、队伍、投票和任务牌录入，减少重复点击；沿用既有事件工厂与仓库，投票与失败牌严格分离，草稿恢复和重复提交保护不得退化。

v0.5.0 进入条件：本 PRD 第 2–5 节专项测试全部通过、最新 main CI 全绿、历史资料兼容测试通过、完成验收报告。
