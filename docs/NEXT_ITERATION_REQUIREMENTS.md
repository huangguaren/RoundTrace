## 3. NX-01：推论语义与证据质量

### 3.1 A04：成功结果与失败牌数量

任务成功只能说明失败牌数低于该任务的失败门槛，不能普遍推导失败牌为 0。

| 输入 | 应有说明 |
|---|---|
| 8 人局第 4 任务、1 张失败牌、任务成功 | 门槛为 2，1 张失败牌仍成功；不能证明全队好人 |
| 门槛为 1、明确记录 0 张失败牌 | 已记录 0 张失败牌；坏人也可以出成功牌，不能证明全队好人 |
| 只记录观察结果为成功，失败牌数未知 | 展示成功这一现场记录；不补填实际牌数，说明成功结果不能确认队员阵营 |
| 失败牌数与观察结果矛盾 | 标出记录冲突，不把矛盾双方同时当作可靠推论前提 |

### 3.2 A12：缺失字段的影响范围

当前 `AvalonEvidenceAnalyzer.kt` 中两类提示需要修正：有明确观察结果时，“缺少失败牌数，无法判断任务成败”不成立；队员不完整时，“本任务不参与好人/坏人计数”与 B34 不符。

要求按字段分别说明：缺少失败牌数会限制坏人数量下界推论；缺少成员会限制对具体玩家的归因。结果明确时继续依照 B34 推进成功/失败计数，`verified` 继续表示可复核性。

### 3.3 确定性推论的前提

至少覆盖失败牌为负、失败牌多于合法队伍人数、重复或越界座位、队伍未知/不完整、观察结果冲突，以及人数或任务编号非法的输入。

按每条规则依赖的前提决定是否输出推论。规则本身的门槛说明可以保留；依赖损坏字段的具体阵营结论应抑制，或转成明确的数据质量提示。等级采用已有 `EvidenceLevel` 中语义合适的类型；不能把不可能输入仅改成较弱断言后继续呈现为事实。

保留所有原始记录和冲突提示。已知牌数有效但成员未知时，可以描述该次任务的数量约束，但不得将其归因到未记录的具体玩家。

**验收**：上述案例有明确断言；正常记录的既有推论、视角隔离和时间边界回归通过；任务计数继续遵守 B34。

## 4. NX-02：读取与追加的一致性

当前 `getBundle` 顺序查询多个表，`observeBundle` 合并四路 DAO Flow；追加前在事务外读取和重放。单次写入的事务性不能直接证明多次读取来自同一版本。

要求：

- 读取包含元数据、成员、身份与有效事件的一致快照；观察者不能看到同一事务中“新事件配旧身份/旧揭晓时间”等混合状态。
- 同局并发首次提交提案时，对 `QUEST_STARTED` 是否存在的判断与写入在同一事务内完成。
- 事务内复核对局存在性及影响本次写入的状态；保留现有规则提示、草稿与现场事实的处理契约。
- 保留跨对局隔离、取消传播、失败整体回滚、写入序号与逻辑位置语义。

**验收**：使用可控制时序的并发/事务测试复现风险并验证修复；同局首次提案只生成一个对应任务开始事件；失败后无半写入；监听中的每一份业务快照符合跨表不变量。

## 5. NX-03：首页与复盘效率

首页目前对同一冷 Flow 有两处收集，其中一处缺少错误处理。统一查询生命周期，保留加载、空态、筛选、错误与重试；查询失败时重试应重新订阅并恢复数据。

复盘目前先建立公开探测快照，再建立目标视角快照，`analyzeAt` 还可能再次建立快照。减少同一输入、位置、视角下的重复工作；有效视角为公开时复用公开快照。复用范围限制在本次输入计算内，继续遵守 B29；跨事件更新不复用旧结论。

**验收**：以订阅计数和快照调用计数证明重复工作减少；以相同输入集记录变更前后耗时。连续切换历史位置、视角及修订/撤销事件后，快照、分析、时间线同步刷新；未揭晓时拒绝上帝视角。

**验收**：工作流文件可审查，构建命令可在对应环境执行；报告与 APK 可定位；远端运行结果如实记录。
