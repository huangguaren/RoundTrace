# NX-06 回滚逻辑重构：从"删除式回滚"到"导航式编辑"

日期：2026-11-02

## 1. 背景与问题

当前行为：
- 点击路线图上的任务号（如"第2任务"）→ 弹出"回到第 N 任务？"对话框
- 点"回滚"→ **删除第 N+1 任务及之后所有事件**（提案、投票、任务牌）
- 用户只是想回去看看/改个名字，结果后面记的所有数据都没了

用户诉求：
1. 点路线图任务号 → **直接导航回那个任务的记录界面**，不删任何数据
2. 如果只是查看、不改任何东西 → 退出后数据原样保留
3. 如果真的修改了某个早期记录（比如改了任务1的任务结果）→ **才提示**哪些后续记录会受影响，让用户确认后才删除/重置

## 2. 需求规格

### 2.1 新交互

| 操作 | 旧行为 | 新行为 |
|---|---|---|
| 点击路线图任务号 | 弹"回滚确认"对话框 | 直接切换到该任务的记录模式，顶部显示"正在编辑：第 N 任务" |
| 在编辑模式下什么都不改，点返回 | 已删除后续数据 | 数据原样保留，切回最新位置 |
| 在编辑模式下修改了一条记录（如改投票/改任务结果） | 已删除后续数据 | 提示"修改第 N 任务的 X 后，以下 N 条后续记录将受影响需要重置：..."，用户确认后才执行 |
| 点击"回滚"按钮 | 删除后续所有事件 | **按钮去掉**，不再需要 |

### 2.2 受影响内容的判定规则

修改第 N 任务的某条记录后，哪些后续记录需要被重置/删除？

| 修改的内容 | 受影响的后续内容 |
|---|---|
| 改了任务 N 的提案（队员/队长） | 任务 N 的投票、任务 N 的结果（因为队伍变了，投票和结果不再适用） |
| 改了任务 N 的投票结果 | 无（投票只影响该提案是否通过，不影响后续任务的记录） |
| 改了任务 N 的任务结果（成功/失败） | 任务 N+1 及之后的所有记录（因为任务胜负计数变了，后续任务的前提可能不成立） |
| 改了任务 N+1 的提案 | 任务 N+1 的投票、任务 N+1 的结果 |

简化规则：
- 改提案/投票 → 只重置当前任务的后续阶段（投票→结果）
- 改任务结果 → 提示"修改任务 N 的结果会影响后续所有任务记录"，让用户确认是否继续

### 2.3 不做的事

- 不做"智能合并"（比如自动保留后续任务但修正计数）——太复杂，用户明确说过"只有修改之后与之相关的内容才会被删除或者重置"
- 不做"小红点提示"（用户提过但优先级低）
- 不改变事件级编辑（点时间线条目直接改）的现有逻辑

## 3. 验收标准

1. 点路线图上的任务号，直接进入该任务的记录界面，不弹删除确认
2. 进入后不改任何东西，点返回，所有数据原样保留
3. 修改一条早期记录后，弹出影响提示，列出会被重置的内容
4. 用户点"取消"→ 不删任何数据，保留修改
5. 用户点"确认重置"→ 只删除受影响的后续记录，不删无关的
