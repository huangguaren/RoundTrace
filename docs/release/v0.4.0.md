# RoundTrace v0.4.0 发布说明

> 版本：0.4.0（versionCode 4）· 日期：2026-11-02
> 基线：v0.3.0（versionCode 3）→ 本版本**首次**同时包含数据库 v4 与逻辑顺序修复
> 源码：https://github.com/huangguaren/RoundTrace

## 1. 一句话

这一版把「记录错了怎么办」这件事做完整了：历史事件可以按 `eventId` 直接编辑，
修订后**留在原来的逻辑位置**而不是被甩到时间线末尾；随后补齐 7 项 P1 数据安全与导入导出问题，并修复记录提案时队长无法稳定上车的交互冲突。

## 2. 数据升级：v3 → v4（重要）

- 首次启动 v4 时，App 会**在迁移之前**自动备份数据库为 `<db>.bak.v3`（与数据库同目录）。
- 备份流程会先执行 `PRAGMA wal_checkpoint(TRUNCATE)`，确保备份包含最近已提交的事务。
  朴素复制主库文件会丢掉 WAL 里最近的事务——QA 用「把 WAL 撑到 20KB」实测复现过这个丢失。
- 若 checkpoint 因其它连接占用而未完成（WAL busy），备份仍会生成，但会被标记为
  **「可能缺最近事务」**，日志降级为警告、**不会**报告「备份完成」。
- 新增两列：`logicalPosition`（时间线位置）与 `revisionSeq`（同一位置上的第几版），
  旧数据按 `supersedesId` 链回填；无法归链的（含跨局链）回退为自身写入序号。

### 回退说明（务必读）

- **不能直接装回只支持 v3 的旧 APK**：Room 的 identityHash 变化后，旧版打不开数据库。
- 回退只能**恢复 `.bak.v3` 备份**，并且会**丢失备份之后产生的所有记录**。
- 恢复前请先确认数据范围；建议在数据库副本上演练一次。

## 3. 行为变化

| 变化 | 说明 |
|---|---|
| 修订历史事件后**留在原位置** | 以前改一条早期记录，它会被排到时间线末尾；现在沿修订链继承原逻辑位置，时间线不再错乱 |
| 历史事件可编辑 | 点击时间线条目即可编辑，范围限定三类：**组队提案 / 组队投票 / 任务结果**；通过-否决决议只读（改它请用「撤销 + 重录」） |
| 复盘选点不再漂移 | 修订不会改变历史长度，「复盘到第 N 条」选中的仍是第 N 条 |
| 任务成败计数口径 | 遵循 `docs/decisions.md` B34：**结果明确即计数**，`verified` 只表示数据可复核性，不再参与胜负判定 |
| 时间线显示关键发言原文 | 「关键言论」里写的话现在会出现在时间线详情（超 60 字截断） |
| 旧对局状态一次性刷新 | 升级后后台逐局重算 `matches.status`（不改「最近活动时间」，不影响首页排序）；若某一局失败则**不写完成标记**，下次启动重试 |
| 身份揭晓完整提交 | 角色揭晓、揭晓时间和状态投影在同一事务提交；写入失败时整体回滚 |
| 队长可上车、可更换 | 首次点座位选择队长；之后座位点击只切换上车状态，队长也能上车/下车；用单独的「更换队长」操作改队长，已选成员保持不变 |
| 头像加载更稳 | 选图保存持久读取授权；头像在后台采样解码并使用有上限的缓存；删除或撤销授权后显示占位，不拿旧缓存伪装成功 |
| 导出包含座位布局 | JSON schema v2 增加座位布局与头像 URI 引用，并兼容导入 v1。头像只导出引用，不包含图片文件；当前设备没有读取授权时会跳过该头像并提示重新选择 |
| 导入边界与批量回滚 | 导入限制文件字节数、条数、文本长度和嵌套深度；回滚按对局和逻辑位置单事务批量撤销，失败时整体回滚 |
| DataStore 备份范围 | Auto Backup 与设备传输排除 `file/datastore/`，避免偏好存储被非预期复制 |

## 4. 修了什么（用户可感知的）

| 现象 | 修复 |
|---|---|
| 揭晓身份后再记录新事件，上帝视角被悄悄关掉 | `revealedAt` 不再被状态回写覆盖 |
| 用 A 局的入口去撤销/修订 B 局的事件 | 事件写入按对局隔离，跨局操作被拒绝且不写入任何行 |
| 撤销或修订后，首页显示的状态和复盘结论对不上 | 四条写入路径统一从事件重算状态 |
| 公开视角能看到某个座位的私有声称 | 可见性收敛到唯一出口（公开事实 / 声称标签 / 分析结论 / 时间线 / 导出）五处全部堵上 |
| 页面被系统回收后，刚选的队伍和票数全丢 | 草稿自动恢复；用户「输入后又清空」的动作不会被旧草稿覆盖 |
| 选完队员马上点确认，提示保存成功但其实没写进去 | 提交闸门与草稿自动保存状态分离，不再互相吞掉 |
| 备份明明缺了最近的数据，日志却说「备份完成」 | 备份结果三态化（未备份 / 完成 / 不完整），日志与返回值同源 |

## 5. 真机手测待补项

2026-11-02 已在 API 34 Android 模拟器执行全部 24 条仪器测试，迁移与队长实际触控路径已验证。以下仍需实体设备或人工可访问性检查：

1. 真机杀进程后草稿与编辑目标的恢复；
2. 多连接占用时 WAL checkpoint-busy 的设备级行为；
3. Compose 大字体与 TalkBack；
4. SAF 头像在重启、撤销授权及跨设备导入后的表现；头像 URI 不含图片本体，跨设备无法读取时需要重新选择。

已执行的迁移与触控仪器测试命令：
```bash
./gradlew :app:connectedDebugAndroidTest
```
